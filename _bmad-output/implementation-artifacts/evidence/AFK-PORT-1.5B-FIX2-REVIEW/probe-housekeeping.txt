### commit message (plain, no trailers?)
Report cumulative token totals as information, and let the gates decide the status

The claude usage adapter summed the end-of-run envelope's input, cache-read and
cache-creation tokens and divided by the routed window. Those members are the
total over every API call a run made, not the context its last call held, so an
83-turn run reported 1,330,455 against a 65,536 window: a ratio of 20.30 for a
run that never occupied more than one window. The band said the story needed a
continuation, and because the gates had failed with no worker signal the thin
result said so too, with no checkpoint and no continuation artifact anywhere.

The adapter now reads num_turns and reports the scope of its own figure. Only a
single-turn envelope is that call's context, and only that scope is divided by a
window; anything else - more turns, or an envelope with no turn count, which
proves nothing about how many calls it summed - is published as a cumulative
total with no ratio, no band and no HIGH_USAGE.

status: continuation_required now comes only from a worker that signalled and
left a valid artifact. A usage band beside failed gates is a sizing note, not a
hand-over: there is nothing there to resume from.
