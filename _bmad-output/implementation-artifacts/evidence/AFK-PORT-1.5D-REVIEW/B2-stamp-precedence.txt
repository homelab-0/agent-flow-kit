# B2 — an explicitly named unusable --pm-stamp is silently reclassified

The stamp below fails the shape check, so its window cannot be resolved.
Only the usage_tokens of the observation beside it changes between cases.

  numeric usage            -> {"reason":"PM_STAMP_UNUSABLE","state":"NOT_EVALUATED","window_source":"NOT_EVALUATED","window_tokens":null}
  cumulative-only adapter  -> {"reason":"PM_USAGE_CUMULATIVE_ONLY","state":"NOT_EVALUATED","window_source":"NOT_EVALUATED","window_tokens":null}
  no usage figure          -> {"reason":"PM_USAGE_UNOBSERVABLE","state":"NOT_EVALUATED","window_source":"NOT_EVALUATED","window_tokens":null}

The window never falls through to the adapter (window_tokens stays null), but
in the last two cases the operator is told the USAGE is unobservable and is
handed that remedy — 'checkpoint at the phase boundaries instead' — with no
mention of the stamp they named. The contract shipped in this same diff says
a stamp named on the command line is 'never silently ignored'.
